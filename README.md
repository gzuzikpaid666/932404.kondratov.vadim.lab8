## О проекте

Веб-приложение для ведения портфолио студента. Сервер принимает HTTP-запросы, проверяет входные данные, выполняет операции с базой данных SQLite и возвращает результат в формате JSON. Браузерный интерфейс (HTML, CSS, JavaScript) работает поверх этого API. Реализованы все четыре CRUD-операции: создание, чтение, обновление и удаление проектов.

Каждый проект имеет название, описание, стек технологий, ссылку и дату. Список всегда выводится по дате: новые проекты сверху. Проекты можно искать по названию, фильтровать по технологиям, смотреть карточками в сетке или списком, а создавать и редактировать в модальном окне.

## Цель работы

Применить все изученные технологии в одном проекте: вёрстку, адаптивный дизайн, интерактивные элементы, работу с базой данных и серверным API, а также провести ревью кода (читаемость, семантика, доступность, производительность).

## Используемые технологии

- **Python** — язык серверной части. Нужна версия **3.9 или новее**.
- **FastAPI** — веб-фреймворк: описывает маршруты, принимает query-параметры и тело запроса, проверяет данные и автоматически строит документацию.
- **Uvicorn** — ASGI-сервер, который запускает FastAPI и принимает HTTP-запросы.
- **SQLite** — реляционная база данных в одном файле `portfolio.db`. Работа ведётся через встроенный модуль `sqlite3`, отдельная установка не нужна.
- **HTML, CSS, JavaScript** — интерфейс без фреймворков и сборки. Статические файлы раздаёт тот же сервер.

Зависимости Python перечислены в `requirements.txt`.

## Модель данных

Таблица `projects` создаётся автоматически при первом запуске сервера из файла `schema.sql`.

| Поле | Тип | Описание |
|---|---|---|
| `id` | INTEGER | Первичный ключ с автоинкрементом. |
| `title` | TEXT | Название проекта. Обязательное, 1–100 символов (`CHECK` в БД). |
| `description` | TEXT | Описание, до 1000 символов. По умолчанию пустая строка. |
| `tech_stack` | TEXT | Технологии через запятую: `Python, FastAPI`. По умолчанию пустая строка. |
| `link` | TEXT | Ссылка на проект: пустая или начинается с `http://` / `https://`. |
| `date` | TEXT | Дата проекта в формате `YYYY-MM-DD` (`CHECK` в БД). Обязательное поле. |

Индекс `idx_projects_date (date DESC)` ускоряет сортировку «новые сверху».

## Реализованная бизнес-логика

1. **Разделение ответственности.** SQL-схема лежит в `schema.sql`, API и работа с БД — в `main.py`, интерфейс — в папке `static/`, запуск — в `app.py`.
2. **Поиск.** Запрос `GET /api/projects?q=текст` возвращает проекты, в названии которых есть эта подстрока. Регистр не важен, в том числе для кириллицы (в SQLite `LIKE` этого не умеет, поэтому используется собственная функция `lower_u`).
3. **Фильтрация по стеку.** Запрос `?tags=Python,FastAPI` возвращает проекты, у которых есть все перечисленные технологии (условие «И»). Регистр не важен, `java` не находится внутри `javascript`.
4. **Сортировка.** По умолчанию `ORDER BY date DESC` (новые сверху), параметр `sort=date_asc` переключает на старые сверху. Внутри одной даты порядок по `id`.
5. **Валидация.** Пустое название, слишком длинные поля, неверная дата и ссылка не в формате `http(s)` приводят к ответу `422 Unprocessable Entity`. Те же правила продублированы в форме (`required`, `maxlength`, `type="url"`, `type="date"`) и в ограничениях `CHECK` самой БД.
6. **Нормализация стека.** При сохранении пробелы у тегов обрезаются, а дубли без учёта регистра убираются: `Python, python , FastAPI` превращается в `Python, FastAPI`.
7. **Обработка ошибок.** Если проекта с указанным `id` нет, сервер отвечает `404 Not Found`.
8. **Демо-данные.** Если таблица пуста, при запуске добавляются 4 демонстрационных проекта.

## Интерфейс

- **Карточки проектов** с названием, датой, описанием, тегами и кнопками «Открыть проект», «Изменить», «Удалить».
- **Вид «Сетка / Список».** Выбор запоминается в `localStorage`.
- **Теги-фильтры** со счётчиками. Клик по тегу (в панели фильтров или в карточке) включает и выключает фильтр, «Сбросить фильтры» очищает поиск и теги.
- **Поиск** с задержкой 250 мс: запрос уходит, когда пользователь перестал печатать.
- **Выбор сортировки** по дате.
- **Модальные окна** `<dialog>`: форма создания и редактирования проекта (одна на оба действия) и подтверждение удаления.
- **Табы** «Проекты» и «Технологии». На второй вкладке видны все технологии со счётчиками, клик по технологии открывает проекты с ней. Табы переключаются и стрелками.
- **Адаптивная вёрстка.** Сетка на `auto-fill` / `minmax` сама подбирает число колонок под ширину экрана, на телефоне карточки идут в один столбец.

## Подготовка и запуск

Требуется Python 3.9+. В VS Code откройте папку проекта (**Файл → Открыть папку...**), затем создайте терминал (**Терминал → Создать терминал**). Убедитесь, что терминал открыт в папке, где находятся `app.py`, `main.py`, `schema.sql` и папка `static`.

При первом запуске создайте виртуальное окружение, активируйте его и установите зависимости:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

- `python -m venv .venv` создаёт отдельное окружение проекта.
- `Activate.ps1` активирует его в текущем терминале.
- `python -m pip install -r requirements.txt` устанавливает зависимости из файла. Повторная установка нужна только после удаления `.venv` или изменения `requirements.txt`.

Запустите сервер:

```powershell
python app.py
```

Файл `app.py` запускает Uvicorn с приложением `app` из `main.py`; `reload=True` перезапускает сервер при изменении кода. В консоли появится строка:

```text
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)
```

Терминал с сервером оставьте открытым; для остановки нажмите `Ctrl+C`. Приложение откроется в браузере по адресу <http://localhost:8000>.

### Если PowerShell блокирует активацию

Windows может запретить запуск `Activate.ps1`. Это ограничение PowerShell. Используйте Python из `.venv` напрямую:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --port 8000
```

### Если запуск не удался

- **`python` не найден** — установите Python 3.9+ и добавьте его в PATH.
- **`No module named ...`** — установите зависимости командой из инструкции выше.
- **`Directory '...\static' does not exist`** — файлы `index.html`, `style.css` и `app.js` должны лежать в папке `static`, которая находится рядом с `main.py`.
- **`FileNotFoundError: schema.sql`** — файл `schema.sql` должен лежать рядом с `main.py`, а не в `static`.
- **`Could not import module "main"`** — терминал открыт не в той папке. Перейдите в папку с `main.py` командой `cd`.
- **Порт занят** — остановите другой запущенный сервер (`Ctrl+C`) или укажите другой порт в `app.py` (параметр `port`).

## Как работает приложение

1. Браузер (или Swagger, или cURL) отправляет HTTP-запрос на маршрут `/api/projects`.
2. FastAPI принимает запрос и проверяет данные: название, ссылку, дату, параметры поиска и сортировки. При ошибке сразу возвращается `422`.
3. Если данные корректны, маршрут выполняет параметризованный SQL-запрос к SQLite.
4. Сервер возвращает JSON и соответствующий код ответа: `200`, `201`, `204`, `404` или `422`.
5. JavaScript получает JSON и перерисовывает карточки, теги и счётчики.

```text
Браузер (HTML + CSS + JS)  →  main.py (маршруты, проверка, SQL)  →  portfolio.db
```

## API

| Метод | Маршрут | Назначение | Параметры / тело запроса | Статус |
|---|---|---|---|---|
| **GET** | `/api/projects` | Все проекты, новые сверху. | Нет | `200 OK` |
| **GET** | `/api/projects?q=...&tags=...&sort=...` | Поиск, фильтр и сортировка. | `q` — часть названия; `tags` — теги через запятую; `sort` — `date_desc` (по умолчанию) или `date_asc` | `200 OK` |
| **GET** | `/api/projects/{id}` | Один проект. | Параметр пути `{id}` | `200 OK` |
| **POST** | `/api/projects` | Добавить проект. | JSON: `title`, `date` (обязательные), `description`, `tech_stack`, `link` | `201 Created` |
| **PUT** | `/api/projects/{id}` | Заменить поля проекта. | Параметр пути `{id}` и JSON как в POST | `200 OK` |
| **DELETE** | `/api/projects/{id}` | Удалить проект. | Параметр пути `{id}` | `204 No Content` |
| **GET** | `/api/tags` | Технологии со счётчиками. | Нет | `200 OK` |

Ошибки: `422 Unprocessable Entity` — неверные данные или параметры; `404 Not Found` — проект с таким `id` не найден.

## Примеры тестирования запросов (cURL)

Примеры выполнены на демо-данных. Названия в JSON написаны латиницей, чтобы кодировка консоли Windows не влияла на результат.

**1. Тест валидации (отправка без `title`):**
```bash
curl -X POST http://localhost:8000/api/projects -H "Content-Type: application/json" -d "{\"date\": \"2026-11-16\"}"
```
*Ответ:* `422 Unprocessable Entity` -> в `detail` указано, что поле `title` обязательное.

**2. Тест валидации (название из пробелов):**
```bash
curl -X POST http://localhost:8000/api/projects -H "Content-Type: application/json" -d "{\"title\": \"   \", \"date\": \"2026-11-16\"}"
```
*Ответ:* `422 Unprocessable Entity` -> в `detail` сообщение `Value error, Название не должно быть пустым`.

**3. Тест валидации (ссылка не http/https):**
```bash
curl -X POST http://localhost:8000/api/projects -H "Content-Type: application/json" -d "{\"title\": \"Test\", \"link\": \"ftp://site.ru\", \"date\": \"2026-11-16\"}"
```
*Ответ:* `422 Unprocessable Entity` -> в `detail` сообщение `Value error, Ссылка должна начинаться с http:// или https://`.

**4. Создание проекта (стек нормализуется):**
```bash
curl -X POST http://localhost:8000/api/projects -H "Content-Type: application/json" -d "{\"title\": \"Portfolio site\", \"description\": \"My personal site\", \"tech_stack\": \"Python,  python , FastAPI\", \"link\": \"https://example.com\", \"date\": \"2026-11-16\"}"
```
*Ответ:* `201 Created` -> `{"id":5,"title":"Portfolio site","description":"My personal site","tech_stack":"Python, FastAPI","link":"https://example.com","date":"2026-11-16"}`

**5. Получение списка (новые сверху):**
```bash
curl http://localhost:8000/api/projects
```
*Ответ:* `200 OK` -> массив проектов; первым идёт `Portfolio site` (2026-11-16), затем `Трекер привычек` (2026-09-14) и так далее по убыванию даты.

**6. Сортировка «старые сверху»:**
```bash
curl "http://localhost:8000/api/projects?sort=date_asc"
```
*Ответ:* `200 OK` -> первым идёт `Лендинг кофейни` (2025-11-30).

**7. Фильтр по одной технологии:**
```bash
curl "http://localhost:8000/api/projects?tags=python"
```
*Ответ:* `200 OK` -> проекты `Portfolio site`, `Бот расписания` и `Магазин книг` (регистр тега не важен).

**8. Фильтр по нескольким технологиям (условие «И»):**
```bash
curl "http://localhost:8000/api/projects?tags=Python,SQLite"
```
*Ответ:* `200 OK` -> только `Бот расписания`, потому что у него есть обе технологии.

**9. Поиск по названию без учёта регистра (в URL закодировано слово «магазин»):**
```bash
curl "http://localhost:8000/api/projects?q=%D0%BC%D0%B0%D0%B3%D0%B0%D0%B7%D0%B8%D0%BD"
```
*Ответ:* `200 OK` -> проект `Магазин книг`, хотя в названии слово написано с заглавной буквы.

**10. Список технологий со счётчиками:**
```bash
curl http://localhost:8000/api/tags
```
*Ответ:* `200 OK` -> `[{"name":"Python","count":3},{"name":"CSS","count":2},{"name":"HTML","count":2},...]`

**11. Изменение проекта:**
```bash
curl -X PUT http://localhost:8000/api/projects/5 -H "Content-Type: application/json" -d "{\"title\": \"Portfolio site v2\", \"description\": \"Updated\", \"tech_stack\": \"Python, FastAPI, SQLite\", \"link\": \"https://example.com\", \"date\": \"2026-11-17\"}"
```
*Ответ:* `200 OK` -> `{"id":5,"title":"Portfolio site v2","description":"Updated","tech_stack":"Python, FastAPI, SQLite","link":"https://example.com","date":"2026-11-17"}`

**12. Несуществующий проект:**
```bash

```
*Ответ:* `404 Not Found` -> `{"detail":"Проект не найден"}`

**13. Удаление проекта:**
```bash

```
*Ответ:* `204 No Content` (тело ответа пустое)

**14. Повторное удаление (записи уже нет):**

## Ревью кода

**Читаемость.** Бэкенд разбит на небольшие функции с одной задачей, валидация вынесена в модель `ProjectIn`. На фронтенде есть единые помощники `h()` (создание узлов) и `api()` (запросы и ошибки). Нет глобальных переменных: код обёрнут в IIFE, состояние лежит в объекте `st`.

**Семантика.** Заголовки `h1`–`h3`, теги `header`, `main`, `section`, `article`, списки `ul/li`, `time[datetime]` для дат, `dialog` для модальных окон, `role="search"`, настоящие `button` и `a` вместо кликабельных `div`.

**Доступность.** У всех полей есть `label`. Табы сделаны по WAI-ARIA и переключаются стрелками. Фильтры и переключатель вида используют `aria-pressed`. Число найденных проектов объявляется через `role="status"`, ошибки формы через `role="alert"`. Кнопки в карточках имеют `aria-label` с названием проекта. Виден фокус (`:focus-visible`), есть skip-ссылка. `<dialog>` сам удерживает фокус и закрывается по Esc. Анимации включаются только при `prefers-reduced-motion: no-preference`.

**Безопасность.** SQL выполняется только с параметрами. Значения вставляются в страницу через `textContent`, поэтому вредоносный HTML не выполнится. Ссылки допускаются только `http(s)`, проверка есть и на сервере, и на клиенте. Внешние ссылки открываются с `rel="noopener noreferrer"`.

**Производительность.** Фильтрация и сортировка выполняются в SQL, а не в браузере. Поиск работает с задержкой (debounce). Приложение использует один CSS и один JS без зависимостей. Сетка подстраивается без медиазапросов. Выбранный вид списка хранится в `localStorage`.

**Что можно улучшить.** Вынести работу с БД в отдельный модуль, как в 7 лабе. Добавить пагинацию при сотнях записей. Хранить теги в отдельных таблицах `tags` и `project_tags` (связь многие-ко-многим). Написать автотесты (`pytest` + `TestClient`). Добавить авторизацию, если портфолио станет публичным.
